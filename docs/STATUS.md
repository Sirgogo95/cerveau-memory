# Implementation status

What exists in the code today, as opposed to what the [ARCHITECTURE.md](ARCHITECTURE.md) designs. Update this file in the same commit as the work it describes.

Last updated: 2026-11-11, on branch `feature/demo-gif`.

**Phase:** v3 done (2026-11-09): the LoCoMo report final, a first eval on the author's own chat history, and the fixes it found. Cerveau is a chat with long-term memory in the browser at `/`, fully local by default on gemma4:e4b (Ollama, a 6 GB laptop GPU): each conversation is consolidated into summaries, facts, tags, and entities; recall brings back past messages, summaries, facts, and a named person's facts as a block; the model can search its memory itself; a viewer at `/memory/` shows and edits what it knows. On LoCoMo's full question set (strict, deepseek-v4-pro): 66.9% fully local (66.3% after a human review of the grades), 76.2% with a cloud model answering ([CERVEAU_LOCOMO_RESULTS.md](CERVEAU_LOCOMO_RESULTS.md) section 6.5). On 60 questions about the author's own ChatGPT chats: 44 right with the memory, 10 without ([PERSONAL_CHATS_EVAL.md](PERSONAL_CHATS_EVAL.md)). What's built is in **Done**; how it works is in the [GUIDE](GUIDE.md).

Near misses (2026-10-18): the subject is stored, the detail asked for isn't ("who is Pedro marrying?"). The model invented a bride in about 4 of 18 answers; one sentence in the system prompt ("if your notes cover the subject but not the detail, say that detail isn't in your notes; never fill it in") brought it to 0 of 8, with near misses 47/48 and memory questions 49/52 (no new refusals). A confidence gate wouldn't have helped: the match is strong, the detail is missing.

The tools are safe: no unwanted search on general questions, no slower ordinary turns, and a search before saying "I don't remember" on absent topics (about 0.7 s). But they added no correct answer on this scenario: automatic recall already found everything it could, cross-language questions included. The one consistent miss ("who asked me to be best man?" about a Spanish conversation on being *padrino*) is a recall problem, not a tool one (Known gaps). A prompt rule to search before saying "I don't remember" changed nothing and was not kept.

e5 compresses similarities (unrelated text scores ~0.75), so its threshold sits near 0.8 and its margin is thin. Ollama's bge-m3 (16-bit) scored the same as the full-precision copy. About 0.2 noise remains even at strict thresholds: some unrelated questions name a person or project that is in memory, which the name signal recalls by design.

## Known gaps and notes

- **"This Saturday" stayed relative at consolidation** (seen 2026-11-11, recording the demo): a conversation saying "my friend turns 30 this Saturday", consolidated three weeks later, kept "this Saturday" in its summary and facts instead of a date, though consolidation is meant to make relative dates absolute (the date rules). Not yet investigated: whether the rule misses "this <weekday>" or the model ignored it.

- **Warm start asks Ollama to load the chat model and bge-m3** in parallel after `runserver`; with bge-m3 on Ollama the server no longer imports PyTorch. Messages sent meanwhile wait for it. Every code change reloads the server and runs it again in the background.
- **A relevant message can be crowded out**: "did my brother like the drawing?" doesn't recall "he loved it, says thanks" (reworded from a real conversation) (0.555, above the threshold) because five closer messages fill the 5 message slots; the summary carries the answer, but the model quoted the wrong message as its reason in 2 of 3 runs. Embedding messages with the one before them was measured four ways (2026-10-18) and not kept: it cost recall on real conversations and didn't raise this message (GUIDE 9.2). Short user messages ("hello", "programming") also add noise; dropping them from the search by meaning was measured and not kept (GUIDE 9.2).
- **Docker Desktop and Ollama don't start on their own** after a restart or sleep: Postgres is unreachable until Docker Desktop runs. The container's restart policy covers the rest once Docker is up.
- **The sentence-transformers embedder contacts Hugging Face on load** (only with that profile; bge-m3 runs on Ollama). Setting `HF_HUB_OFFLINE=1` after the first download keeps it fully local.
- **Long texts are embedded whole up to 8,192 tokens** (bge-m3; about 30,000 characters). One vector for a very long text still blurs its details: shared files are split into passages instead (see [ATTACHMENTS.md](ATTACHMENTS.md)).
- **The retrieval threshold is calibrated on Claude-written cases** (`min_score = 0.53` for bge-m3, with short replies left out, the tag signal and activation on). The first personal case (21 questions on 4 real conversations) agrees: every memory question found at 0.53; too small to move it. **Checked on 25 real chats (2026-11-09, PERSONAL_CHATS_EVAL.md 6g):** there recall is generous (about 14 memories per question, 39% from the evidence; a never-said question still gets about 10), but 0.57 answered 38 of 60 and 6 messages instead of 10 answered 41, against 44 now, so 0.53 and the caps stay. Drift, carry-over and activation are still calibrated on written cases only. It is a trade-off: 0.50 recalls more (93% hit rate) with more noise (1.8), 0.54 less with less. The tag signal is a small nudge (w_tag 0.05); it was measured with model-written tags, so it is only as good as consolidation's tags.
- **Facts are good, not perfect.** Measured live: a non-durable "fact" sometimes slips in ("will book the hotel that evening"), some facts are phrased as events ("the user moved the wedding to March 3"), a judge miss can leave a near-duplicate (1 in 47 labelled pairs), and the same fact in two languages isn't always merged. All visible and fixable in the Facts tab.
- **A capitalized ordinary word mid-sentence can match a name**: "I ate Ramen" would find Ramón (one letter off). Rare in English and Spanish writing; `fuzzy_names = false` turns typo matching off.
- **Some words don't cross languages.** "Best man" doesn't reach a Spanish conversation about being *padrino* (0.43 to 0.49, below the thresholds), while "padrino boda" or "someone getting married" do (0.57). Neither recall nor a search in English finds it; the model would have to search in Spanish. A short, generic note in the memory block made the model answer "I don't remember" without searching; Cerveau's short replies are now left out of recall, and the model searched in one of two runs, but in English, which doesn't reach the Spanish word.
- **A wrong answer in the conversation gets repeated.** In a long conversation that already holds a wrong answer (the eval database had one, from before the period fix), the 4B model tends to repeat it rather than use the fresh notes. A new conversation, or Forget in the memory viewer, clears it.
- **A retrieved message is shown alone**, without the turn around it; a short reply like "yes, do that" can surface without context. The model can now open it with `read_memory`, which returns the messages around it.
- **Language detection knows three languages** (English, Spanish, French) and stays silent on short or unclear messages; other languages get no hint.
- **The chat page and the memory viewer have no login.** Fine for a single local user (`runserver` listens on 127.0.0.1 only). The viewer can make Cerveau forget, so add authentication to both before exposing them on a network.
- **Hardware:** RTX 3060 Laptop, 6 GB VRAM, 16 GB RAM. `qwen3.5:4b` uses 3.6 GB at 16,384 context (32,768 spills to the CPU) and bge-m3 0.66 GB: both stay loaded on the GPU (5.2 GB in use).
- **Type checking** is `basic` ([pyrightconfig.json](../pyrightconfig.json)), with Django stubs from `django-types`; dev tools are in [requirements-dev.txt](../requirements-dev.txt).
- **The worker is a second process:** `python manage.py db_worker` must run for consolidation; without it, closed episodes wait (the sweep queues them at the next server start). Commands are in [ARCHITECTURE.md: Development setup, step 5](ARCHITECTURE.md#development-setup).
- **Consolidation and chat share the GPU model:** a job running while you chat makes the next reply wait for it (Ollama serves one request at a time by default). The sweep at server start keeps most consolidation out of chat time.
- **Consolidation quality depends on the 4B model:** in the live check, attribution was right after the prompt fix, but tags still drifted toward topics Cerveau raised ("compliance"). Near-duplicate tags are merged by meaning at 0.83; pairs below that (home/housing 0.71, doctor/medical 0.77) stay two tags.
- **Relative dates in memory** ("next week") stay relative to when they were said; the memory lines carry dates, but the model may not adjust them.
