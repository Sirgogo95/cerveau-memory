# Evaluation: Cerveau on my own chat history

**Status:** first round done (2026-11-03 to 07): 25 of the user's ChatGPT chats imported and consolidated, 60 questions answered and graded (by the user and by deepseek-v4-pro), four faults found and fixed in code, a clean check on new questions, and comparisons with qwen3.5:4b, gpt-oss:120b and gemma4:e4b with thinking (sections 6b to 6f). The purge path tested and its one gap fixed (2026-11-09); open: the steps before publishing (STATUS). gemma4:e4b is the local model, with thinking a per-turn switch on the chat page, off by default (2026-11-07); dated message notes and entity blocks are on.
**Related:** [CERVEAU_LOCOMO_RESULTS.md](CERVEAU_LOCOMO_RESULTS.md), [LOCOMO_FINAL_RUNS.md](LOCOMO_FINAL_RUNS.md), [COMPACTION_EVAL.md](COMPACTION_EVAL.md), [features/ENTITY_PROFILES.md](features/ENTITY_PROFILES.md)

## 1. Why

LoCoMo is two people chatting with each other, in English, generated by models. Cerveau is built for something else: **one person talking to an assistant**, across many projects, over months, in three languages.

This eval uses my real chat history from ChatGPT to answer the question LoCoMo can't: **does Cerveau work in day-to-day use?**

It also tests an importer, which is a product feature in its own right: bringing an existing chat history into Cerveau solves the cold-start problem (an empty memory on day one).

## 2. What it measures

1. Answer accuracy on questions about my own past conversations, by category (section 5).
2. Retrieval: whether the messages holding the answer reach the notes.
3. Noise: how much irrelevant memory comes back for questions that should recall nothing.
4. Segmentation: whether long imported chats split where the topic changes.
5. Attribution: whether Cerveau tells what I decided apart from what the assistant only suggested.
6. Cross-language recall, on real mixed-language data.

## 3. Privacy rules (decided before anything else)

These chats contain work, plans, and details about other people.

- **The data never leaves the machine** unless a step explicitly says otherwise. It lives in `evals/cases/personal/chats/`, git-ignored, and never goes into the public repository, the blog post, or any shared file.
- **Fully local by default**: gemma4:e4b consolidates and answers (the local model since 2026-10-24; qwen3.5:4b is retired); a local model grades. A cloud run (Ollama Cloud) is allowed only on a reviewed subset, after reading the provider's data policy.
- **Excluded chats**: anything mainly about another person's private matters (health, relationships, finances, legal), credentials or keys, and anything I wouldn't want stored even locally.
- **Published results** contain numbers only, plus at most a few examples rewritten so no real person, place, or private detail is identifiable.
- **The one exception so far (the user's decision, 2026-11-04):** to write the questions from any device, the text of the 25 chosen chats (610 messages) and the questions themselves are stored in a private claude.ai artifact, the Question Desk (only the user can open it). The eval is therefore not fully local from that point on: the chats' text has been on claude.ai. Deleting that artifact removes them there.
- **A purge path**: deleting the folder and running `purge_memory` on the eval database removes everything; the eval database is never cloned to the dev or prod one.

## 4. The data

### 4.1 Export

- **ChatGPT**: Settings → Data controls → Export data. The download includes the conversations as JSON (`conversations.json`, a tree of messages per conversation).
  **Checked 2026-11-03** (the user's export, kept outside the repository): 209 conversations (2025 and 2026), split over `conversations-000.json` to `-002.json`. Each has `conversation_id`, `title`, `create_time`, `update_time`, `current_node` and a `mapping` of nodes (`id`, `parent`, `message`); a message has `author.role` (`user`, `assistant`, plus `system` and `tool`), `create_time`, and `content` with a `content_type`: `text` and `multimodal_text` (images; `parts` mixes strings and asset references) are kept, `thoughts` and `reasoning_recap` (the model's reasoning) are skipped. About 800 attached files come as `file-*.dat`. Each conversation carries `is_do_not_remember`: chats the user marked that way in ChatGPT are left out by default. The node's `children` list is absent, so the continued branch is found only by walking back from `current_node` through `parent`.

Formats change: check the exported files before writing the converter, and keep a sample of each format in the tests (anonymized).

### 4.2 Selection

- **30 to 50 chats**, spread over several months.
- A mix of topics, so the eval tests telling projects apart: personal projects, work, plans, hobbies, learning, and Cerveau itself (no more than about a quarter of the set).
- Chats in **Spanish and French** as well as English, and a few that switch language.
- Several **projects revisited weeks apart**, where decisions changed in between.
- A few **long chats** (100+ messages), for segmentation and the running summary.

### 4.3 The importer

A management command, built as a real feature, not an eval-only script:

```text
python manage.py import_chats --source chatgpt path/to/export --dry-run
python manage.py import_chats --source chatgpt path/to/export --select ids.txt
```

Behavior:

| Rule | Detail |
|---|---|
| Roles | User messages stay user; assistant replies become assistant messages |
| Timestamps | Each message keeps its original time, in the user's timezone |
| Episodes | Each chat starts a new episode; the time-gap and drift rules split it further, as live. Replaying drift means embedding every message in order and running the subject-change check, the slowest part of an import, so the command shows progress |
| Branches | ChatGPT stores edited and regenerated replies as branches: import the branch that was continued. The export's `current_node` marks its last message; walk back from it through each message's parent |
| Attachments and images | Recorded as a note (`[shared a file: name]`); file contents only if the export includes them and the type is supported |
| System and tool messages | Skipped, except tool results the user saw and referred to |
| Duplicates | A chat already imported (same source and conversation ID) is skipped |
| Selection | `--select` takes a list of conversation IDs, so the privacy review decides what goes in |
| Consolidation | Queued for each closed episode, in date order, so facts supersede in the right order |

The importer writes to the **eval database** for this eval; in normal use, it writes to the user's own memory. Built 2026-11-03 as above, for ChatGPT, with two decisions: the export ids are kept in a table of their own (`ImportedMessage`: source, conversation, the export's message id, the stored message), and chats go in whole, one after another in order of their first message (interleaving them by time would make every switch between chats look like a change of subject). A reply split over several messages in the export is one reply; images, files and voice messages become text notes; the model's reasoning is skipped. Not done here: the running summary, activation and carry-over, which act turn by turn in live use (section 8).

## 5. The questions

**First version: 30 questions, a qualitative study (decided 2026-11-04).** With 25 chats, the first round is 30 questions, read one by one, rather than the 100 to 150 below. At around 65% right, the 95% interval on 30 questions is about plus or minus 17 points, so this round reports counts, not percentages ("21 of 30 right, 2 invented details, 5 'I don't remember' when the answer was there"), with a few anonymized examples. What follows from the size:

- **Graded by hand** by the user: no local grader to validate against 50 labels (6.2 applies again when the set grows).
- **No tuning and no held-out split**: nothing is changed because of these questions; they run once, as a final check.
- **Runs:** P1 (fully local) is the main one, P0 (no memory) the baseline; P2 is skipped (a difference between them would have to be very large to show on 30 questions).
- **The spread:** never said 5 (inventing things about the user is the failure that matters most), single fact 4, multi-hop 4, changed decision 4 (the stale value must not be given), temporal 3, cross-language 3, attribution 3, inference 2, recent context 2. Only 2 of the 25 chats hold any Spanish or French (one each), so cross-language may come up short; a category the chats can't support passes its questions to the ones above it, said so in the write-up.
- **Growing it later:** more chats and more questions; these 30 stay unchanged.

The questions are written on the Question Desk, a private claude.ai artifact (section 3: the user chose to upload the 25 chats for it), with Markdown rendered: the 25 chats with each message clickable as evidence, the category targets above, each question saved to the artifact's database in the format of 5.3 and read from there. The same page also exists as a local file (`evals/cases/personal/chats/questions.html`, git-ignored); its Load file brings questions written there into the Desk.

### 5.1 Categories

| Category | Example | Mirrors |
|---|---|---|
| Single fact | "What embedding model did I pick for Cerveau?" | LoCoMo single-hop |
| Temporal | "When did I decide to use Django for Cerveau?" | LoCoMo temporal |
| Multi-hop | "Which of my projects use Postgres?" | LoCoMo multi-hop |
| Inference | "Which of my projects would suit a small local model?" | LoCoMo open-domain |
| Changed decision | "What's the current default for message slots?" (5, later 10) | Cerveau-specific |
| Cross-language | An English question about something said only in Spanish | Cerveau-specific |
| Attribution | "Did I decide to use Redis, or was it only suggested?" | Cerveau-specific |
| Never said | A plausible question about something never discussed | LoCoMo adversarial |
| Recent context | "What were we talking about last time?" | Cerveau-specific |

### 5.2 Writing them

- **100 to 150 questions**, at least 10 per category.
- Each question records: the gold answer, the evidence, the category, and the language.
- **Evidence uses the export's own IDs** (the conversation ID and the message ID, or its position in the chat), never Cerveau's message IDs: those change if the chats are imported again or the eval database is reset, and every question would break. The importer keeps the mapping, and the runner turns export IDs into Cerveau IDs.
- **Ask about what I said and decided**, not about what the assistant claimed; assistant replies can be wrong, and grading against them would reward repeating errors.
- **Write the questions before running Cerveau** on the imported chats, so the system's behavior can't shape them.
- For changed decisions, the gold answer is the latest value; the old one is recorded as `stale`.
- For never-said questions, the gold answer is "not mentioned".

### 5.3 File format

Same style as the existing case files, so the runner can share code with `python -m evals`:

```json
{
  "scenario": "personal-chats",
  "questions": [
    {
      "id": "pc-017",
      "category": "changed_decision",
      "language": "en",
      "question": "What's the current default for message slots in Cerveau?",
      "gold": "10",
      "stale": ["5"],
      "evidence": [
        {"source": "chatgpt", "conversation": "3f2a...", "message": "b81c..."},
        {"source": "chatgpt", "conversation": "9d07...", "message": "41e5..."}
      ]
    }
  ]
}
```

### 5.4 Held-out set

- Split the questions **two thirds tuning, one third held out**, stratified by category.
- The held-out third isn't looked at until the final runs. Any threshold or prompt change is measured on the tuning part only.

## 6. Runs

### 6.1 Configurations

| Run | Consolidates | Answers | Grades | Purpose |
|---|---|---|---|---|
| **P1** | gemma4:e4b (local) | gemma4:e4b | local grader | Fully local, the app's defaults: the main number |
| **P2** | gemma4:e4b | gemma4:e4b, entity blocks off | local grader | Whether entity blocks (on by default since 2026-10-22) help on real data |
| **P0** | none | gemma4:e4b, recent window only | local grader | Baseline without memory |
| **PC** | gpt-oss:120b (cloud) | gpt-oss:120b | gpt-oss:120b + second grader | Only on a reviewed subset, optional |

Same frozen configuration as the LoCoMo final runs, temperature 0 for answering and grading. "Today", for every question, is just after the last imported chat (as LoCoMo uses the day after its last session), so "what were we talking about last time?" refers to the imported history, not to whatever else is in the database.

### 6.2 Grading

- **Exact answers** (names, numbers, dates, model names): normalized string match first.
- **The rest**: a grader model, with the same prompt as LoCoMo's.
- **Grading sends content too.** A cloud grader receives each question, its gold answer, and Cerveau's answer, which hold the private details. A run whose answers are local but whose grading is in the cloud is **not** fully private, and is reported as such.
- **A local grader** for the privacy-default runs. It must be checked first: hand-label 50 answers, measure its agreement, and report it. A small local grader was 13 to 16 points too lenient on LoCoMo, so if no local model grades reliably, grade by hand or use the cloud grader on a reviewed subset only. On LoCoMo, deepseek-v4-pro (cloud) agreed with the user's hand labels on 85 of 100 and tracked the human-reviewed score within a point on both audited runs (CERVEAU_LOCOMO_RESULTS.md sections 6.7 and 6.8): the natural candidate for a reviewed subset.
- **Never-said**: correct if the answer declines or says it wasn't mentioned.
- **Changed decision**: giving the stale value counts as wrong, and is counted separately.
- **Attribution**: correct only if the answer says who decided.

### 6.3 Runner

```text
python -m evals.personal_chats --import evals/cases/personal/chats/ --consolidate gemma4-e4b-background
python -m evals.personal_chats --answer --temperature 0 --out p1.jsonl
python -m evals.personal_chats --answer --temperature 0 --set entity_block.enabled=true --out p2.jsonl
python -m evals.personal_chats --answer --temperature 0 --window-only --out p0.jsonl
python -m evals.personal_chats --compare p1.jsonl p2.jsonl
```

Like the LoCoMo runner: memory built once and copied per question, answers saved as they come (and resumable), 95% intervals, sign tests between runs.

## 6c. Three fixes found by the first round, and the runs after them (2026-11-06)

The first round's misses pointed to three real faults in the tool, fixed in code (GUIDE 4.9, 4.10, 4.11):

1. **Summaries and facts in the wrong language.** gemma4:e4b, left to name the language, wrote 37 of the 77 summaries and 16 of the 100 facts of these English chats in Portuguese. The language is now worked out in code from the user's messages and fixed in the reply schema. Re-imported into a fresh database (`cerveau_chats_v2`) and re-consolidated: none in Portuguese (77 episodes, 117 facts).
2. **A suggestion read as the user's decision.** Imported ChatGPT replies sit in the notes as "Cerveau" lines, pasted whole; a 5,000-character plan buried the user's one line beside it. Earlier replies in the notes are now clipped to 600 characters on one line, and the memory header says they are suggestions, not the user's decisions.
3. **No searching.** gemma4:e4b never called the search tool. A reply that only declines ("I don't remember", short) is now replaced by a search on the user's words and a second answer.

**The runs after, deepseek-v4-pro grading (strict).** These re-runs are *after fixes found by these same 30 questions*, so they are not a clean test; a clean check needs new questions (section 6d).

| Run | Memory | Code | Right |
|---|---|---|---|
| First round | as first consolidated | before | 23 of 30 |
| Fixes 2 and 3 | as first consolidated | after | 25 of 30 |
| All three | re-consolidated (`cerveau_chats_v2`) | after, first fallback | 23 of 30 |
| All three, final | re-consolidated | after, fallback refined (a long hedge kept) | 22 of 30 |

Read with the interval (about plus or minus 17 points on 30 questions), the total did not move. What changed is where the misses are: the targeted failures are gone in every run after the fixes (no invented figure, the attribution question answered as "recommended, not decided", every summary and fact in English), and the model now searches when it declines (7 to 13 answers per run). The other changes are churn: the same wrong date judged differently by the grader, an answer asking for context, a right answer about a suggested framework marked wrong because it doesn't also name the user's stack. Tuning stopped there: further changes would have chased noise in these same 30 questions.

**Regression check, the tool-use eval** (gemma4:e4b, written cases, two runs per setting): with the fallback 55 of 56 right, without it 52 of 56 (stored answers 26 of 26 against 24 of 26; never said 7 of 8 against 6 of 8; near misses 12 of 12 both). The eval's checker missed some correct declines ("I don't have your wife's name", "I don't have that detail", "No encuentro nada"); their phrasings were added, and both settings were re-run with it.

The suggested-tool answer now says "Cerveau suggested" but opens with "yes". What remains looks like the small model's limit, not the notes'.

**Checked on LoCoMo (2026-11-07, at an outside reviewer's suggestion):** the fully local setup (gemma4:e4b memory from the cache, read with `--no-language-pin`; answering at temperature 0; deepseek-v4-pro grading) on a sample of 50 normal questions (5 per conversation) and 50 trick questions, with and without thinking, the same code otherwise.

| LoCoMo sample | Without thinking | With thinking |
|---|---|---|
| Normal questions | 41/50 | 42/50 (3 turned right, 2 wrong) |
| Trick questions | 42/50 | 38/50 (1 turned right, 5 wrong) |
| Seconds per answer (median) | about 2 to 3 | about 7 to 13 |

Thinking made gemma accept false premises: the five trick questions it lost are fabrications (another person's hobby, pet or description given as the one asked about; "Andrew makes jewelry from recycled materials"), where without thinking it said it had no such note. The personal chats couldn't show this: their never-said questions are about topics never raised, not traps that swap two people, and both settings got all 10 right. The same pattern as the prompt nudges on LoCoMo: pushed to work harder, the small model fills gaps instead of declining.

**Decided after this check (the user, 2026-11-07): thinking is a switch on the chat page, off by default.** `gemma4-e4b.toml` is back to `think = false` with the 1,536-token reserve; a turn sent with **Think first** on goes to the same model with thinking on and a 4,096-token reserve (`with_thinking`, GUIDE 8.3 and 6.9). It is worth turning on for a question about who decided or suggested what, and left off for the rest.

## 6g. Recall's threshold on real memory (2026-11-09)

Automatic recall's threshold (`min_score` 0.53 for bge-m3) was calibrated on the written eval cases (`python -m evals --sweep`, 2026-10-16). Checked here on the imported chats (`cerveau_chats_v2`) with the 60 questions and their evidence, with a new command, `python manage.py recall_sweep`: each question's recall replayed at each threshold (no model called), a memory counted as found when it belongs to an episode holding the evidence.

| min_score | Evidence found (50 questions) | Share of what's kept from the evidence | Kept per question | Kept for a never-said question |
|---|---|---|---|---|
| 0.49 | 94% | 34% | 16.6 | 14.6 |
| 0.53 (now) | 94% | 39% | 13.7 | 10.4 |
| 0.57 | 90% | 47% | 9.9 | 7.1 |
| 0.61 | 82% | 53% | 6.8 | 5.4 |
| 0.65 | 64% | 56% | 4.5 | 3.7 |

On real chats, recall is generous: at 0.53 most sources fill their caps (10 messages, 3 episodes, 5 facts), and a never-said question still gets about 10 memories (even at 0.65, about 4: exact-word and activation boosts lift some scores above 1). On the written cases a higher threshold costs much more (hit rate 92% at 0.53, 84% at 0.57, 78% at 0.59).

Whether the extra memories hurt was measured on the answers (gemma4:e4b, temperature 0, deepseek-v4-pro grading, `personal_chats_eval --min-score` and `--set`), against the current setting's 44 of 60 (6d's grouped runs):

| Setting | Right of 60 | Turned right | Turned wrong |
|---|---|---|---|
| Now: 0.53, up to 10 messages | 44 | | |
| 0.57 | 38 | 1 | 7 |
| 0.53, up to 6 messages | 41 | 1 | 4 |

**Kept as it is.** Both narrower settings answered worse: gemma4:e4b uses the extra memories more than it is misled by them (the never-said questions were 10 of 10 in every run). The same direction as on LoCoMo, where more notes per question helped. Runs of these 60 questions vary by 2 to 3, so 0.53 with 6 messages is within noise, 0.57 is not.

## 8. Risks and limits

- **One person's data.** The results describe how Cerveau works for me; they say nothing about other people's habits.
- **Writing my own questions** favors things I remember well. Include questions about chats I'd half forgotten, found by skimming older exports.
- **Questions written after reading the chats** can be easier than real recall needs. Some questions should be written from memory first, then checked against the chats.
- **Imported history isn't live use.** The importer runs consolidation in a batch; in live use, the running summary, activation, and carry-over act turn by turn. This eval doesn't measure those.
- **Grading cost and privacy pull against each other**: a reliable grader may need the cloud, and the privacy default says local. Section 6.2 decides.
